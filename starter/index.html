The scene is a pure function

SHT 1 OF 2 · REV 1

Everything the canvas above does is decided by apply(p), where p is scroll progress from 0 to 1. No internal state, no “current step”, no accumulators. The same p always produces the same frame.

That is why scrubbing backwards works, why ?p=0.62 freezes an exact moment, and why a screenshot script can shoot the whole film as a contact sheet in one command. 

const seg01 = (p, [a, b]) => clamp01((p - a) / (b - a));
const ease  = (t) => t * t * (3 - 2 * t);        // smoothstep
const ss    = (p, a, b) => ease(seg01(p, [a, b]));

function apply(p, t = 0) {
  const build = ss(p, ...SEG.build);
  const zoom  = ss(p, ...SEG.zoom);
  camScale    = mix(mix(1, 3.2, zoom), 0.30, ss(p, ...SEG.scale));
  fillAlpha   = build * (1 - 0.85 * heat);
  // ...one line per visual property, across the whole film
}

Choreography lives in a data map

SHT 2 OF 2 · REV 1

Retiming the entire film means editing one object. Cutting a beat never touches drawing code. Click a beat to jump the scene to its midpoint.

  • outline 0.00 – 0.08
  • build 0.08 – 0.20
  • zoom 0.20 – 0.30
  • examine 0.30 – 0.55
  • revise 0.55 – 0.75
  • verify 0.75 – 0.90
  • scale 0.90 – 1.00

Three things encode this timing and will drift if you let them: the SEG map, the pin length (end: "+=500%"), and the phase labels. Comment each one pointing at the other two.
